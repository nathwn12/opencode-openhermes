# oh-proto

## When to Use
When you need to sanity-check a data model, state machine, or UI direction before committing to implementation. Prototypes are disposable.

## Workflow
1. Determine what question the prototype answers (data model, state flow, UI direction)
2. Build the minimal prototype — just enough to answer the question
3. Let the user play with it
4. Collect feedback
5. Decide: discard, iterate, or promote to production

## Modes
- **Terminal prototype** — for state/business logic questions
- **UI prototype** — several radical design variations from one route

## Anti-patterns
- Polishing a prototype ("it's just a prototype!" — it never is)
- Falling in love with prototype code (it's throwaway by design)
- Prototyping when you already know the answer
